# boltgym

A small gym for one CAD skill, moving a bolt hole pattern from one part to another, where the agent answers in OpenSCAD and the verifier checks that the answer still holds when the sliders move.

This is an independent student prototype. It is not affiliated with, endorsed by, or reviewed by Adam. All parts and all "defective answers" in it are synthetic and generated by the code in this repo.

## The problem

A text-to-CAD model can produce a part that looks right at the sizes it was written for and breaks as soon as someone edits a dimension. A hole written as `translate([46, 66.5, -1])` is in the right place on a 137.5 mm plate. Widen the plate and the hole stays where it was, even though the instruction said "identical offsets from the top-right corner".

A reward that only renders the default geometry cannot see that. If the goal is to train or evaluate a model on a CAD skill, the reward has to check the design intent, and for parametric CAD that means checking the model at more than one parameter setting.

## Why this matters to Adam specifically

I checked the following myself. Everything else in this README about Adam is my guess.

- Adam's Summer 2027 residency posting lists "building gyms and training models with RL for specific CAD skills" as a possible project (ycombinator.com/companies/adam/jobs).
- Adam's open-source app CADAM outputs parametric OpenSCAD, shows the top-of-file variables as sliders, and applies slider changes without calling the model again (github.com/Adam-CAD/CADAM, README).
- CADAM reads those sliders with a regular expression in `shared/parseParameters.ts`. The comment above it says the model is told to emit Customizer-style annotations (`name = 10; // [1:50]`, `/* [Group] */`) and carries a TODO: "Use AST parser instead of regex. Regex breaks on multi-line expressions, nested arrays, and any clever OpenSCAD trick."
- CADAM publishes 13 benchmark models as `.scad` files with a table of how many controls each one exposes (`benchmarks/README.md`).

So the two things this repo does are aimed at those: a gym whose action is OpenSCAD in the same annotation format, and a parameter reader that works on tokens instead of a regex. I do not know how Adam builds its own gyms or what its commercial product uses internally.

## What it does

1. **Task generator.** `make_task(seed)` builds a source plate with a hole pattern, a target plate of a different size, and an instruction. Two skills: `transfer` (same diameters, same offsets from a named corner) and `clearance` (source holes are tapped M3 to M10, target needs clearance holes).
2. **OpenSCAD interface.** `scadtask.source_scad(task)` and `target_scad(task)` render both parts as OpenSCAD files with Customizer-style parameters. The agent returns an edited target file.
3. **Evaluator.** `scad.py` tokenizes, parses and evaluates a subset of OpenSCAD and reports the plate and its round through holes. It has an operation budget and a call depth limit, and every failure comes back as `ScadError` with a line number.
4. **Verifier.** `scadtask.verify_scad(code, task)` checks the holes at the sizes in the file, then sets `plate_width`, `plate_height` and `plate_thickness` to three other values (by editing the declarations, the way a slider would) and checks again. It returns a score, the stage that failed, and a message.
5. **Parameter reader.** `params.extract(code)` returns the sliders in the shape of CADAM's `Parameter` type. `params.set_params(code, {...})` edits values and leaves every other byte alone.
6. **Environments.** `ScadEnv` takes a whole file per step with up to three attempts and feeds the error message back. The original `BoltEnv` with tuple actions (`add`, `move`, `dia`, `del`, `submit`) and its baselines are still here.

## Architecture

```
boltgym.py    task generator, geometric verifier (Hungarian matching), BoltEnv
scad.py       tokenizer -> parser -> evaluator -> read_plate()
params.py     extract(), set_params(), is_color(), built on scad.tokenize
scadtask.py   source_scad/target_scad, verify_scad, ScadEnv,
              reference writers, 14 injected defects, random token mutants
agents.py     baselines for BoltEnv (random, copy, search, scripted, bandit)
bench.py      prints every table below, writes bench_results.json
demo.py       one-minute tour
test_*.py     56 tests
```

`verify_scad` is the only place the pieces meet: `params.extract` to confirm the three plate parameters are still plain numbers, `scad.read_plate` for geometry, `boltgym.verify` for matching and manufacturing rules, `params.set_params` for the resize.

## Key decisions and tradeoffs

- **Check the answer at several sizes, including thickness.** The sweep changes thickness as well as width and height. I measured what happens with thickness held fixed: of the random one-token mutants that were wrong only when resized, a width and height sweep caught 45 of 70 on the dev split and 48 of 77 on the held-out split. With thickness in the sweep all of them were caught, because the rest were holes whose depth no longer followed the plate.
- **Three resized plates, although one was enough here.** One resized plate already caught every resize-only mutant in both splits. I kept three because the cost is small (13.4 ms per call in total) and my mutants are simpler than real model mistakes.
- **A narrow evaluator that says so.** The parser accepts most of the language. The evaluator only understands plates: `cube`, `cylinder`, `translate`, `rotate` about z, `difference`, `union`, `for`, `if`, `let`, user modules and functions. It refuses everything else with a message. It parses all 13 of CADAM's benchmark models and evaluates none of them, since they use BOSL2, extrusions and rotations about x and y.
- **Tokens instead of a regex for parameters.** The reader only looks at top-level declarations before the first real `module` or `function` token, so commented-out code, a semicolon inside a string, a declaration that spans lines, and nested arrays are handled. I wrote it from the annotation format, not by porting CADAM's code, and I did not run CADAM's parser, so I am not claiming specific inputs where theirs fails beyond what their own TODO says.
- **Edits go through the text.** The resize uses `set_params` on the source instead of injecting values into the evaluator. That is slower, but it tests the path a slider takes, and it catches an answer that renamed or removed a parameter.
- **Sequential assignment.** OpenSCAD lets a later assignment in the same scope override an earlier one before either is used. My evaluator runs assignments in order. `params` does follow the last-declaration rule.
- **Kept from the first version.** Hungarian matching inside the geometric verifier (greedy matching under-scored 26.9% of 5000 perturbed states) and the dense reward shape.

## Install and usage

Python 3, standard library only. Nothing to install.

```
python demo.py                 # one-minute tour
python -m unittest             # 56 tests, about 10 seconds
python bench.py scad           # verifier tables, 2 to 3 minutes
python bench.py                # everything, about 7 minutes
python scad.py part.scad       # plate and holes of a file as JSON
python params.py part.scad     # sliders of a file as JSON
python boltgym.py task 36      # one task as JSON
```

To run the checks against CADAM's published models, clone their repo somewhere else and point at it. The files are read, not copied into this repo.

```
CADAM_DIR=/path/to/CADAM python -m unittest test_params
CADAM_DIR=/path/to/CADAM python bench.py scad
```

In code:

```python
import scadtask
env = scadtask.ScadEnv(attempts=3)
obs = env.reset(36)                 # instruction, source_scad, target_scad
obs, reward, done, info = env.step(my_openscad_text)
print(info["stage"], info["error"])
```

## Limitations and next steps

- No neural policy and no language model has been run in `ScadEnv`. The writers are scripts. I have no API access in this project, so I cannot say how a real model scores.
- I could not install OpenSCAD here, so the evaluator has never been compared with the real one. It agrees with the task generator's own geometry on every source file in the tests, which is a weaker check.
- The evaluator handles flat plates with round through holes only. No extrusions, no rotation about x or y, no libraries, no `children()`. Real CADAM output is far outside it.
- The parts are synthetic rectangles and the defects are ones I chose. The mutant test is closer to unbiased but still starts from my three code styles.
- I did not run CADAM's own `parseParameters` (it is GPL-3.0 code that I only read), so there is no side-by-side comparison, only the published control counts.
- Clearance sizes are the normal-fit column (M3 3.4, M4 4.5, M5 5.5, M6 6.6, M8 9, M10 11). I checked them against one public chart, not against the ISO 273 document.

Next steps I would take: run the real OpenSCAD binary as a second oracle on generated answers, widen the evaluator to linear extrusions and rotated holes so an L-bracket like CADAM's honeycomb benchmark can be a task, and put an actual model in the loop to see which of the 14 defects it really produces.
